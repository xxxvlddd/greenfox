## 1. Всё на одной схеме

```
                               ┌────────────────────────────┐
                               │          Человек           │
                               └──────────────┬─────────────┘
                                              │  щелчки, ввод
┌─────────────────────────────────────────────▼──────────────────────────────────────────────┐
│ ОКНО  (renderer/)                                                                          │
│ Экраны, окна ввода, мастер первого запуска, панель ассистента.                             │
│ Только рисует. К диску, базе и сети доступа нет — всё просит через мост.                   │
│ Уйти со своей страницы, открыть новое окно или чужую страницу не может.                    │
└─────────────────────────────────────────────┬──────────────────────────────────────────────┘
                                              │  window.api.…  — около 70 разрешённых вызовов
┌─────────────────────────────────────────────▼──────────────────────────────────────────────┐
│ МОСТ  (main/preload.js)                                                                    │
│ Полный список того, что окну разрешено попросить. Больше ничего.                           │
│ Главный процесс отвечает только своей странице; путь к файлу — только выбранный.           │
└─────────────────────────────────────────────┬──────────────────────────────────────────────┘
                                              │  IPC: «дай экран», «запиши», «спроси ассистента»
┌─────────────────────────────────────────────▼──────────────────────────────────────────────┐
│ ГЛАВНЫЙ ПРОЦЕСС  (main/)                                                                   │
│                                                                                            │
│ ipc.js — вход: каждый вызов окна ведёт в один из модулей                                   │
│   ├─ экраны (только чтение): overview, expenses, capital, forecast, plans,                 │
│   │  calendar, payments, settings, onboard                                                 │
│   ├─ запись: entry.js — единственный, кто пишет учёт в базу                                │
│   ├─ ассистент: assistant.js, comments.js ─────────────►  OpenRouter  (сеть)               │
│   ├─ курсы валют: fx.js ───────────────────────────────►  сайт ЦБ РФ  (сеть)               │
│   ├─ обновления: updates.js ───────────────────────────►  GitHub      (сеть)               │
│   └─ данные: backup.js, csvio.js, integrity.js, rename.js                                  │
│                                                                                            │
│ book.js ─► РАСЧЁТНОЕ ЯДРО (core/): прогон операций, деньги в копейках, показатели          │
└─────────────┬─────────────────────────────────────────────────┬────────────────────────────┘
              │                                                 │
              │  SQL                                            │  safeStorage
 ┌────────────▼───────────┐                        ┌────────────▼───────────┐
 │ БАЗА  SQLite           │                        │ Связка ключей macOS    │
 │ finances.db            │                        │ ключ, которым          │
 │ учёт, настройки,       │                        │ зашифрован ключ        │
 │ шифр ключа ассистента  │                        │ ассистента             │
 └────────────┬───────────┘                        └────────────────────────┘
              │  копии и выгрузки
 ┌────────────▼───────────┐
 │ backups/  — копии базы │
 │ CSV — выгрузка таблиц  │
 └────────────────────────┘
```

Три правила, на которых держится всё остальное:

- **Окно ничего не может само.** Оно рисует и просит. Читать базу, писать
  в неё, ходить в сеть может только главный процесс.
- **Пишет в учёт один модуль — `entry.js`.** Любая запись — из окна ввода,
  из карточки ассистента, из мастера, из сверки — проходит его проверки и
  ложится одной транзакцией: либо всё, либо ничего.
- **Баланс не хранится, а вычисляется.** Остаток счёта получается прогоном
  всех операций от стартового остатка. Поэтому ошибку записи нельзя
  «спрятать»: она видна при сверке с банком.

## 2. Части приложения

Приложение — Electron: внутри работает тот же движок, что в браузере
Chrome, плюс Node.js для доступа к файлам. Процессов два: **окно**
(показывает) и **главный процесс** (думает и хранит).

### 2.1 Окно — `app/renderer/`

| Файл | Что это |
|---|---|
| `index.html` | каркас: боковая панель, шапка, место для экрана, слой мастера |
| `app.js` | переходы между экранами, тема, запуск при старте |
| `overview.js`, `expenses.js`, `capital.js`, `forecast.js`, `plans.js`, `calendar.js`, `payments.js`, `settings.js` | семь экранов учёта и «Настройки»: из готовых чисел собирают разметку |
| `forms.js` | все окна ввода: операция, перевод, счёт, платёж, цель, кредит, сверка, категории, выгрузка и загрузка |
| `assistant.js`, `comments.js` | панель ассистента и комментарии на экранах |
| `onboard.js`, `onboard-fx.js` | мастер первого запуска; приветствие — знак из точек на холсте |
| `splash.js` | заставка при каждом открытии окна: тот же знак из точек, пока открывается учёт |
| `update.js` | плашка «Вышла новая версия» |
| `keys.js` | горячие клавиши |
| `fmt.js`, `motion.js`, `charts.js` | формат денег и дат, движение, графики |
| `*.css`, `fonts/`, `fox.svg` | оформление по макетам, шрифты внутри приложения, знак |

Окно изолировано: у него нет доступа к Node.js, а правила страницы
(Content-Security-Policy) запрещают ей любые сетевые запросы — даже если в
разметку что-то попадёт, оно никуда не отправит данные.

### 2.2 Мост — `app/main/preload.js`

Список функций `window.api.*`, которые окно может вызвать: `overview()`,
`addOperation(op)`, `saveRecon(r)`, `assistantAsk(q)` и так далее — около
семидесяти. Каждая превращается в вызов (IPC) главного процесса.

### 2.3 Главный процесс — `app/main/`

```
main.js        запуск: имя, папка данных, база, окно, меню
│
ipc.js         все вызовы окна — одним списком (его же подключают живые проверки);
               отвечает только своей странице, пути — только выбранные человеком
├── Экраны — только читают
│   ├── overview.js      «Обзор»: доступно, лимит на сегодня и завтра, кредитка
│   ├── expenses.js      «Расходы»: траты за период, категории, журнал операций
│   ├── capital.js       «Капитал и долги»: активы, долги, запас прочности, сверка
│   ├── forecast.js      «Прогнозы»: остаток вперёд, кредит, цели
│   ├── plans.js         «Планы»: очередь покупок
│   ├── calendar.js      «Календарь»: дни, траты, заметки
│   ├── payments.js      «Обязательные платежи»: расписание и что оплачено
│   ├── settings.js      «Настройки»: счета, категории, параметры, курсы
│   └── onboard.js       мастер первого запуска (и читает, и записывает разом)
│        каждый из них ──► book.js ──► core/ (прогон и показатели)
├── Запись
│   ├── entry.js         проверки правил учёта, запись одной транзакцией, отмена
│   └── prefs.js         настройки: значения по умолчанию и что в них можно записать
├── Деньги в других валютах
│   └── fx.js            курсы ЦБ: загрузка, курс на день, пересчёт
├── Обновления
│   └── updates.js       раз в сутки — есть ли новая версия на GitHub; проверка
│                        подписи автора, скачивание со сверкой, замена после выхода
├── Ассистент
│   ├── assistant.js     разговор с моделью, функции чтения данных, карточки операций
│   ├── comments.js      комментарии на экранах и авто-отчёт за неделю или месяц
│   ├── openrouter.js    обращения к OpenRouter
│   └── secrets.js       ключ ассистента: шифр в базе, ключ шифра — в связке ключей
└── Данные
    ├── db.js + schema.sql  открыть базу, создать таблицы, обновить схему
    ├── backup.js        копии базы
    ├── csvio.js         выгрузка таблиц в CSV и загрузка журнала из CSV
    ├── integrity.js     проверка целостности: пересчёт с нуля и сверка
    └── rename.js        переезд папки данных после переименования в GREENFOX
```

### 2.4 Расчётное ядро — `app/core/`

| Файл | Что делает |
|---|---|
| `money.js` | деньги — целые копейки (BigInt), округление «банковское»; дробных рублей в расчётах нет |
| `ledger.js` | **прогон** (`replay`): остатки всех счетов и долг по кредиту на конец каждого дня; сверка со справочниками |
| `report.js` | показатели: доступно на счетах, ближайшие платежи, лимит на день, график кредита, грейс |
| `csv.js` | чтение и запись CSV; текст, похожий на формулу (`=`, `+`, `−`, `@` в начале), выгружается с апострофом |

Ядро не знает ни про базу, ни про окно: получает списки и возвращает
числа. Своих чисел у него нет: стартовые остатки, кредит и лимиты карт
приходят из базы. Поэтому его можно проверять отдельно — и оно проверено против
прежнего расчёта на Python до копейки.

## 3. Где лежат данные

```
~/Library/Application Support/GREENFOX/          ← данные приложения
├── data/
│   ├── finances.db                              ← БАЗА: весь учёт и настройки
│   ├── finances.db-wal, finances.db-shm         ← служебные файлы базы, пока она открыта
│   └── backups/
│       └── greenfox-ГГГГ-ММ-ДД-ЧЧММСС-причина.db  ← копии (прежние — finances-…)
├── location.json                                ← только если базу перенесли в другую папку
└── Cache, Local Storage, …                      ← служебное окна (размер, кэш)

~/Library/Application Support/GREENFOX — песочница/   ← песочница, создаётся заново при каждом запуске

Связка ключей macOS: запись «Финансы Safe Storage»     ← ключ, которым зашифрован ключ ассистента
                                                         (имя прежнее — см. раздел 7)
```

```
greenfox/                                        ← исходники (этот репозиторий)
├── main/  core/  renderer/                      ← приложение
├── build/  tools/                               ← иконка и её сборка
├── scripts/install.sh                           ← установка одной командой
└── release/                                     ← после npm run dist: GREENFOX.app и .dmg
```

Выгрузка таблиц ложится в папку, которую выбрали в окне выбора, — в папку
`GREENFOX — выгрузка ГГГГ-ММ-ДД ЧЧ-ММ/`.

Базу можно перенести в другую папку («Настройки» → «Данные»): приложение
делает копию, сверяет число операций в копии и только тогда переключается,
а новый путь записывает в `location.json`. Старый файл остаётся как ещё
одна копия.

## 4. Модель данных

### 4.1 Принципы

| Принцип | Что значит на деле |
|---|---|
| Баланс вычисляется | В базе нет колонки «текущий остаток». Есть остаток счёта на дату открытия и все операции; остаток на любой день — прогон. |
| Деньги — целые копейки | Все суммы — `INTEGER` в копейках (у валютных счетов — в центах). 1 234,56 ₽ хранится как `123456`. |
| Операция — всегда в рублях | `transactions.amount` — рубли (у валютной операции — по курсу ЦБ на её дату). По нему считаются траты. У валютной стороны — ещё своя сумма. |
| Сверка — эталон | `accounts.reconciled_balance` — не остаток, а то, что человек увидел в банке. Расчёт сравнивается с ним; расхождение закрывается корректирующей операцией, история не переписывается. |
| Категории — закрытый список | Операция ссылается на категорию из `categories`; новую заводят явно и с типом. |
| Правила — в самой базе | Ограничения `CHECK` и внешние ключи: сумма больше нуля, дата — ГГГГ-ММ-ДД, у расхода есть счёт списания, у перевода — оба счёта. |

### 4.2 Связи таблиц

```
                                ┌──────────────────┐
                                │    categories    │  закрытый список категорий с типом
                                └────────┬─────────┘
                  category ┌─────────────┼──────────────────┐ category
                           ▼             ▼ category         ▼
┌──────────────────────────────┐  ┌──────────────┐  ┌──────────────┐
│         transactions         │  │  recurring   │  │   planned    │
│ операции: расход, доход,     │  │ расписание   │  │ очередь      │
│ перевод                      │  │ платежей     │  │ покупок      │
└──────┬───────────────┬───────┘  └──────┬───────┘  └──────────────┘
       │ account_from  │ account_to      │ account_id
       ▼               ▼                 ▼
┌───────────────────────────────────────────────────┐
│                     accounts                      │ ◄── savings_goals.account_id     (где копится цель)
│ счета: остаток на дату открытия, валюта, сверка   │ ◄── balance_snapshots.account_id (снимки сверок)
└──────────────────────────┬────────────────────────┘ ◄── liabilities.account_id       (долг кредитки)
                           │ currency  (RUB / USD / EUR)
                           ▼
                  ┌──────────────────┐
                  │     fx_rates     │  курс ЦБ на каждый день по валюте
                  └──────────────────┘

Отдельно, без связей:  settings — настройки и служебные значения;
                       day_notes — заметки к дням календаря;
                       resolved_questions — снятые вопросы к платежам;
                       ai_usage, ai_comments, ai_reports — расход, комментарии и отчёты ассистента.
```

### 4.3 Таблицы

**`transactions` — операции.** Главная таблица учёта.

| Поле | Что хранит |
|---|---|
| `id` | номер операции |
| `date` | дата, ГГГГ-ММ-ДД |
| `seq` | порядок внутри дня — от него зависят проценты по кредиту, если в один день два платежа |
| `direction` | `расход` / `доход` / `перевод` |
| `amount` | сумма в рублях, в копейках, всегда больше нуля |
| `amount_from`, `amount_to` | у валютного счёта — сколько ушло с него / пришло на него в его валюте; у рублёвой стороны — пусто |
| `account_from`, `account_to` | счёт списания и зачисления: у расхода — только первый, у дохода — только второй, у перевода — оба |
| `category` | категория из закрытого списка; у перевода — «Переводы между своими» |
| `description`, `flag` | описание и метки («спонтанная», «по плану», «корректировка» …) |
| `source` | откуда запись: приложение, ассистент, сверка, импорт |
| `currency` | валюта поля `amount` — всегда RUB |
| `created_at`, `updated_at` | когда записана и правлена |

**`accounts` — счета.**

| Поле | Что хранит |
|---|---|
| `id` | код счёта латиницей (из названия) — на него ссылаются операции |
| `name`, `bank`, `type` | название, банк, тип: дебетовая карта, кредитная, наличные, текущий, брокерский, крипто |
| `currency` | RUB / USD / EUR; кредитка — только RUB |
| `start_balance`, `start_date` | остаток в валюте счёта на дату, с которой счёт в учёте — отсюда начинается прогон |
| `is_payment` | платёжный: входит в «Доступно на счетах» и в лимит на день |
| `credit_limit`, `grace_note` | у кредитки — лимит и правило грейса словами |
| `reconciled_balance`, `reconciled_at` | эталон последней сверки: что было в банке и когда |
| `sort_order`, `archived` | порядок в списках и архив (старые операции на счёт ссылаются, поэтому он не удаляется) |

**`categories`** — `name`, `type` (доход, базовые, обязательные, дискреционные,
сбережения, прочее, техническая), `note`, `active`, `sort_order`. Служебные
категории («Переводы между своими», «Платежи по кредитам», «Прочее»,
«Инвестиции» и др.) не переименовываются и не удаляются — на них опирается
расчёт.

**`recurring` — регулярные платежи (расписание, а не факт).** `name`,
`amount` и `amount_max` (если сумма плавает) — в валюте своего счёта,
`direction`, `period` (месяц, неделя, квартал, год), `day_of_month` /
`day_of_week` / `month_of_year`, `category`, `account_id`, `obligatory`
(входит в обязательную нагрузку), `active`, `end_date`, `note`.

**`liabilities` — кредиты и долги.** `creditor`, `type`, `start_debt` и
`start_date` (долг на начало учёта), ставка — `rate_bp` (годовая, в сотых
процента) и `rate_month` (точная месячная дробью), `monthly_payment`,
`payment_day`, `close_date`, `initial_amount`, эталон сверки долга. Остаток
долга не хранится — его ведёт прогон: каждый платёж по кредиту делится на
проценты и тело.

**`planned` — очередь покупок.** Цена от и до, нужность и срочность, срок,
категория, «есть чем заменить», стоимость владения в месяц, статус
(в очереди, куплено, отменено).

**`savings_goals` — цели накоплений.** Название, цель и срок (или «просто
копим»), счёт хранения, плановый взнос. Накоплено — это остаток счёта
хранения, вручную не ведётся.

**`balance_snapshots` — снимки сверок.** На какую дату какой остаток был
подтверждён по каждому счёту. Это механизм проверки, а не источник
остатков.

**`fx_rates` — курсы валют.** `date`, `currency`, `rate` — рублей за единицу
× 10 000 (84,9057 ₽ = `849057`), `source` — `cbr` (сайт ЦБ) или `manual`
(вписан руками). Курс на день — последний известный не позже этого дня.

**`settings` — настройки и служебное (ключ — значение).**

| Ключ | Что это |
|---|---|
| `ui.theme`, `ui.density`, `ui.startScreen`, `ui.weekStart` | вид: тема, плотность, первый экран, начало недели |
| `ui.onboarded` | мастер первого запуска пройден или пропущен |
| `calc.reserve`, `calc.horizon`, `calc.levels`, `calc.zones` | расчёты: неснижаемый резерв, горизонт лимита, пороги трат, зоны запаса прочности |
| `ai.model`, `ai.access`, `ai.monthLimit`, `ai.report`, `ai.comments` | ассистент: модель, полномочия, лимит в долларах, отчёт, комментарии |
| `ai.key.enc` | ключ OpenRouter — **только шифр** |
| `data.backupEvery`, `data.backupKeep` | копии: как часто и сколько хранить |
| `schema_version` | версия схемы базы (сейчас 7) |
| `fx.fetchedAt`, `fx.error`, `fx.asked.<валюта>` | когда и с какого дня спрашивали курсы у ЦБ, последняя ошибка |
| `upd.check` | проверять ли обновления: `on` / `off` |
| `update.checkedAt`, `update.available`, `update.error`, `update.later` | когда проверяли; проверенное подписанное описание новой версии; последняя ошибка; «Позже» — до какого времени и для какой версии |

**Остальные:** `day_notes` (заметка к дню календаря), `resolved_questions`
(вопросы к платежам, закрытые кнопкой «Решено»), `ai_usage` (обращения к
ассистенту: модель, токены, стоимость — **без текста вопросов и ответов**),
`ai_comments` (последний комментарий на каждый экран), `ai_reports`
(авто-отчёты, прочитан или нет).

### 4.4 Как из таблиц получаются числа на экране

```
 accounts ─────────┐  остатки счетов на дату открытия
 liabilities ──────┤  долг по кредиту и ставка                 book.load()
 transactions ─────┤  все операции по порядку      ─────────►  core/ledger.js  replay()
 fx_rates ─────────┘  курс на день (валютные счета)                │
                                                                   ▼
                                     история по дням: на конец каждого дня с операцией
                                       bal  — остаток каждого счёта в рублях по курсу дня
                                       nat  — он же в валюте счёта
                                       loan — долг по кредиту
                                                                   │
 recurring ──► book.recurring() ──► платежи в рублях ──┐           │
                                                       ▼           ▼
                                  core/report.js: доступно на счетах, ближайшие платежи,
                                  лимит на день, на сколько хватит, капитал, грейс …
                                                                   │
                                                                   ▼
                                  экранный модуль (overview.js, capital.js …) — готовые
                                  числа, деньги — копейки строкой, без единого числа,
                                  вписанного руками
                                                                   │
                                                                   ▼

```

Пример — «Можно тратить в день» на «Обзоре»:

```

− обязательные платежи до поступления  по расписанию, до ближайшего дохода
− неснижаемый резерв                   из «Настроек» → «Расчёты»
= свободно
÷ дней до ближайшего поступления
= можно тратить в день
```

### 5.2 Показать экран (чтение)

```
окно                         главный процесс                          база и ядро
 │ api.overview()             │                                        │

 │                            │ overview.build(db, сегодня)            │
 │                            │ book.load() ──────────────────────────►│ SELECT счета, операции,
 │                            │                                        │ кредит, курсы
```

Каждый показ экрана пересчитывает всё заново от сырых данных — кэша

### 5.3 Записать операцию

```
окно ввода                   главный процесс                          база
 │ api.addOperation(op)       │                                        │
 │──────────────────────────► │ ipc «add-operation» → write()          │
 │                            │ entry.checkOp — правила учёта:         │
 │                            │  • категория из списка, тип подходит   │
 │                            │  • счета есть и не в архиве            │

 │                            │ entry.insertOps — одна транзакция ────►│ INSERT transactions
 │ ◄──────────────────────────│ { ok, id, undo }                       │
 │ тост «Отменить» (минута)   │ после записи, в фоне:                  │
 │ экран перерисован          │  • копия базы, если пора               │

```

Ошибка в любом пункте — запись не делается, окно показывает причину
словами («Категория: выберите из списка»). Так же, через `entry.js`,
пишут карточки ассистента, мастер первого запуска и сверка.

### 5.5 Валютные счета и курсы

```
сайт ЦБ РФ  ◄── даты и код валюты ──  fx.js  ──► fx_rates (курс на каждый день)
                                        ▲
                                        │ только если есть счёт в USD или EUR;
                                        │ при запуске, раз в три часа,
                                        │ после записи; без связи — последний курс,
                                        │ можно вписать вручную
расход 20 $ с долларовой карты:
  amount_from = 2000 (центы)  ──► остаток карты в долларах
  amount      = 170000 (копейки, 20 $ × 85,00 ₽ на дату) ──► траты в рублях
покупка валюты (перевод 8 300 ₽ → 100 $):
  amount = 830000 (ушло с рублёвой карты),  amount_to = 10000 (пришло в долларах)
```

### 5.6 Ассистент

```
окно                 assistant.js (главный процесс)                         OpenRouter → модель
 │ вопрос             │                                                       │
 │──────────────────► │ инструкция: словарь терминов, карта экранов,          │
 │                    │ список счетов и категорий, данные открытого экрана    │
 │                    │ ─────────────────────────────────────────────────────►│
 │                    │ ◄─── модель просит: overview / period / operations /  │
 │                    │      forecast / capital / calendar / payments /       │
 │                    │      plans / check_ledger                             │
 │                    │ считает на компьютере и отправляет результат ────────►│
 │                    │ ◄─── ответ блоками (answer) или карточки операций     │
 │                    │ фильтр служебного текста, формат денег                │
 │ ◄──────────────────│ ответ; карточки → сохранение через entry.js           │
```

- Модель **ничего не пишет сама**: операции она предлагает карточками, а
  записываются они по тем же правилам `entry.js`. Сразу, без кнопки, —
  только если в «Настройках» выбран такой уровень полномочий и человек сам
  попросил внести операции («Ввод операций»). Карточки из ответа на вопрос
  человек сохраняет сам: модель читает описания операций, а описание бывает
  чужим — комментарий к входящему переводу может быть написан как команда
  модели.
- Всё, что пришло от модели и от OpenRouter (ответ, названия моделей,
  ошибки), выводится в окно как текст, не как разметка.
- Комментарии на экранах и авто-отчёт (`comments.js`) — те же данные
  экранов одним запросом; комментарий обновляется, только если данные
  экрана изменились (сравнивается отпечаток).
- На компьютере хранится: расход (`ai_usage`), комментарии, отчёты. История
  разговора — только в памяти, последние 12 реплик, до перезапуска.

### 5.7 Копии базы

| Когда | Причина в имени файла |
|---|---|
| при запуске и после записей — по расписанию (раз в день / неделю / при каждом изменении) | `auto` |
| по кнопке в «Настройках» | `manual` |
| перед переносом базы в другую папку | `move` |
| перед загрузкой журнала из CSV | `import` |
| перед объединением категорий | `merge` |

Копию делает сам SQLite: она согласована, даже если в ту же секунду идёт
запись. Хранится столько последних, сколько задано (по умолчанию 30).

### 5.8 Выгрузка и загрузка CSV

- **Выгрузка** (`csvio.js`): восемь таблиц в формате старого учёта —
  журнал, счета, категории, платежи, кредиты, планы, цели, снимки. Если
  есть валютные операции, у журнала две колонки в конце: `amount_from`,
  `amount_to`. Ячейка, которая начинается с `=`, `+`, `−` или `@` и не
  является числом, получает впереди апостроф: иначе Excel или Numbers
  выполнили бы её как формулу. Загрузка апостроф снимает.
- **Куда и откуда**: только в папку и из файла, которые человек выбрал в
  системном окне выбора. Файл журнала больше 20 МБ не читается.
- **Загрузка журнала**: сначала предпросмотр — какие строки годятся, какие
  нет и почему, какие уже есть (дубли); потом копия базы и запись одной
  транзакцией. Операции по валютным счетам так не грузятся — им нужна
  сумма в валюте счёта.

### 5.9 Мастер первого запуска

Открывается сам на чистой базе (или из «Настроек», пока нет ни одной
операции). Три шага собирают счета с остатками, категории и регулярные
платежи; запись — одним вызовом `onboard-apply`, внутри — те же функции
`entry.js`, одной транзакцией. Итог мастера («Можно тратить в день»)
считается тем же расчётом, что «Обзор».

### 5.10 Обновления

```
главный процесс (updates.js)                      GitHub
───────────────────────────────────────────────   ───────────────────────────────────
1  раз в сутки (вскоре после запуска, потом
   проверка каждый час — прошли ли сутки) ──────► какой релиз последний?
                                                  ◄── номер версии и список файлов
2  новее установленной? нет → ничего не показывать
3  да → описание update.json и его подпись ─────► ◄── update.json, update.json.sig
4  подпись автора сошлась, версия в описании
   та же, что у релиза → плашка в окне
5  «Обновить» → установщик ─────────────────────► ◄── GREENFOX-arm64.dmg
   размер и SHA-256 — как в подписанном описании
6  образ открыт: то же приложение (ru.local.finances),
   та же версия, подпись кода цела → копия рядом
7  копия базы → выход → сценарий замены ставит новую
   версию на место старой и запускает её
```

- **Подпись релизов** — Ed25519, как у Sparkle. Закрытый ключ есть только у
  автора (`~/.config/greenfox/release-key.pem`, `tools/release-key.js`),
  открытый зашит в `updates.js`. Без подписи, с чужой подписью, со старым
  описанием под новым номером, с другим размером или суммой — не
  предлагается и не ставится.
- **Где замена невозможна** — запуск из образа диска или из «Загрузок»,
  нет прав на папку — плашка даёт команду установки для «Терминала».
- **Выключается** в «Настройках» → «О программе»; в песочнице и при запуске
  из исходников обновления не проверяются.

### 5.11 Песочница

`Песочница.command` запускает то же приложение с ключом `--sandbox`: своя
папка «GREENFOX — песочница», пустая база или копия настоящей (настоящая
открывается только на чтение). Можно показать пример ошибки расчёта и
медленного расчёта. Настоящий учёт не затрагивается.

## 6. Что уходит с компьютера

| Куда | Когда | Что передаётся | Что не передаётся |
|---|---|---|---|
| **OpenRouter** (openrouter.ai) → выбранная модель | только если добавлен ключ: вопрос в панели, комментарии на экранах (если включены), авто-отчёт | вопрос; данные, нужные для ответа: названия счетов и категорий, суммы, даты, описания операций | ключ шифрования, файл базы, вся база целиком |

Шрифты лежат внутри приложения.

## 7. Надёжность и безопасность

**Окно и всё, что в нём показывается**

- **Окно изолировано**: без Node.js (`nodeIntegration: false`), в песочнице
  Chromium (`sandbox: true`), со своим миром для моста
  (`contextIsolation: true`). Electron 44 — поддерживаемая версия со
  свежими исправлениями Chromium.
- **Правила страницы** (Content-Security-Policy): скрипты — только файлы
  приложения, без `eval` и встроенных скриптов; сеть, фреймы, плагины,
  отправка форм и подмена базового адреса запрещены.
- **Окно не уходит со своей страницы**: переходы по ссылкам, перенаправления,
  новые окна и встроенные страницы (`webview`) отклоняются в главном
  процессе. Иначе чужая страница оказалась бы в окне, у которого есть мост
  к базе.
- **Функции приложения отвечают только своей странице**: каждый вызов
  проверяет, что пришёл из главного кадра окна с `index.html` приложения
  (`ipc.fromPage`).
- **Чужой текст не становится разметкой**: названия, описания, заметки,
  ответы модели и ошибки сети выводятся через экранирование. Проверка-атака
  (`npm run xss`) подставляет вредную разметку во все поля учёта и в ответы
  сети и обходит все экраны, окна ввода, панель ассистента и мастер.
- **Разрешения**: камера, микрофон, геопозиция, уведомления, устройства —
  отклоняются без вопроса человеку.

**Файлы**

- **Пути выбирает человек**: выгрузка, загрузка журнала и перенос базы
  принимают только ту папку или тот файл, что вернуло системное окно
  выбора. Придуманный окном путь отклоняется.
- **«Показать в Finder»** открывает только папки базы, копий и последней
  выгрузки, и только папки — файл, открытый так, запустился бы.
- **Выгрузка не превращается в формулы** — см. 5.8.

**Данные**

- **Все записи — через `entry.js`** и одной транзакцией; плюс проверки в
  самой базе (`CHECK`, внешние ключи). Отмена — в течение минуты.
- **Журнал базы с опережающей записью (WAL)**: падение посреди записи не
  оставит базу полузаписанной.
- **Ключ ассистента** — в базе только шифр (`settings.ai.key.enc`); ключ
  шифра — в связке ключей macOS, в записи «Финансы Safe Storage». Имя
  прежнее намеренно: Electron ищет запись по имени приложения при запуске,
  поэтому приложение на время запуска называется «Финансы», а потом —
  GREENFOX. Без этого сохранённый ключ после переименования перестал бы
  расшифровываться. Окно полного ключа не получает — только маску.
- **Обновление схемы** (`db.js`): новые колонки добавляются по факту их
  отсутствия, шаг можно безопасно повторить. Версия хранится в
  `settings.schema_version`.
- **Проверка целостности** («Настройки» → «Данные»): пересчёт с нуля,
  сверка с эталонами, операции без счёта или категории, валютные операции
  без своей суммы, нет курса, счета в минусе, ссылки на архив.
- **Своих финансов в коде нет**: ни остатков, ни счетов, ни кредита. Числа
  владельца для проверок лежат в `test/legacy/` — в сборку и в репозиторий
  они не входят, а проверка `render` ищет их в коде и документах приложения.

**Сборка**

- **«Предохранители» Electron** (fuses в `package.json`): собранное
  приложение не запускается как обычный Node (`ELECTRON_RUN_AS_NODE`), не
  читает `NODE_OPTIONS`, не открывает отладчик по `--inspect`; код грузится
  только из `app.asar`, и его целостность проверяется при запуске.
- **Подписи Apple нет** — только самоподпись. macOS покажет предупреждение
  при первом запуске скачанного браузером приложения.
- **Лицензии внутри приложения**: GPL самого GREENFOX, Electron и Chromium —
  в `Contents/Resources`, шрифтов — рядом с ними в `renderer/fonts`. Если
  какой-то из них не попал в сборку, она останавливается
  (`tools/after-pack.js`).
- **Обновления внутри приложения** ставятся, только если описание релиза
  подписано ключом автора, а установщик совпал с ним по размеру и сумме; см. 5.10.
- **Установка одной командой** (`scripts/install.sh`): скачивает последний
  релиз с GitHub, сверяет SHA-256 и только потом ставит; чужое приложение с
  тем же именем не трогает, учёт не трогает.

## 8. Проверки

У автора приложение проверяется четырьмя наборами: расчётное ядро против
прежнего расчёта на Python (22 проверки), расчёты и разметка экранов без
окна (664), настоящее окно — заставка, ввод, переходы, шрифты, мастер,
плашка обновления (416) и
проверка-атака: вредная разметка во всех полях учёта и в ответах сети не
исполняется, окно не уходит со своей страницы (50). Сеть в проверках
подменяется. Наборы работают на настоящем учёте автора, поэтому в
репозиторий не входят.

## 9. Словарь

| Слово | Что значит |
|---|---|
| **Electron** | способ сделать приложение для Mac на технологиях браузера: окно — это страница, главный процесс — программа с доступом к файлам |
| **Главный процесс / окно** | две части приложения: одна хранит и считает, другая показывает |
| **IPC** | сообщения между окном и главным процессом: «дай экран», «запиши операцию» |
| **SQLite** | база данных в одном файле; не нужен сервер |
| **Транзакция** | группа изменений, которая записывается целиком или не записывается вовсе |
| **Прогон (replay)** | пересчёт остатков всех счетов по всем операциям от стартовых остатков |
| **BigInt, копейки** | целые числа без ограничения размера; деньги в них считаются без ошибок округления |
| **WAL** | способ записи SQLite, при котором сбой посреди записи не портит базу |
| **CSP** | правила страницы окна: что ей можно загружать и куда обращаться |
| **safeStorage, связка ключей** | системное шифрование macOS: ключ шифра хранит система, а не приложение |
| **Схема базы** | список таблиц и колонок; её версия растёт, когда добавляется новое |
